# Требования к agent-travel-playground

Согласованная базовая версия: 22.10.2026. Документ определяет поведение продукта и границы
текущего сценария. Команды запуска и настройки находятся в [README](../README.md),
правила разработки — в [AGENTS.md](../AGENTS.md).

## Назначение

Самостоятельная песочница для тестирования агентов, организующих поездки на мероприятия
(конференции). Пользователь подключает своего агента, даёт ему внешний бриф (вне сервиса)
и оценивает поведение по состоянию броней и регистраций на сервере.

Сервис предоставляет каталоги и операции бронирования/регистрации. Выбор предложений, план
действий и решение о завершении остаются агенту. MCP-клиент и агентный фреймворк выбирает
пользователь. Пример клиента в `examples/` необязателен и не должен решать задачу за агента.

Автоматическая проверка итоговой поездки (grader) в этой версии **не входит** в MCP-поверхность
агента и отложена.

## Пользовательский процесс

1. Оператор запускает сервис, настраивает общий мир в JSON и выдаёт Bearer-токен попытки.
2. Студент подключает агента и передаёт ему задание вне MCP (текст брифа / golden question).
3. Агент через MCP просматривает мероприятия, рейсы и гостиницы, регистрируется на событие
   и бронирует перелёты и проживание.
4. Оператор смотрит журнал и ведомость; оценка соответствия брифу — вне агентского MCP
   (вручную или будущим grader).

Приложение может работать локально или быть опубликовано для общего доступа.

## Конфигурация мира

Конфигурация — один JSON с тремя списками: `events`, `flights`, `hotels`.

- Мероприятие: `id`, `name`, `description`, `location`, `start_date`, `end_date`,
  опционально `email_required` (по умолчанию false).
- Рейс: `id`, `origin`, `destination`, `depart_date`, `arrive_date`, `price_rub`.
  Рейс в списке считается доступным для бронирования.
- Гостиница: `id`, `name`, `location`, `nightly_price_rub`, `available_nights`.
- Цены — целые неотрицательные числа в учебных рублях. Даты — `YYYY-MM-DD`.
- ID уникальны внутри каждого списка. Ошибочные поля, типы и даты отклоняются при загрузке.
- Проверка структуры не обязана искать решение задачи. Штатные примеры должны быть
  выполнимы; пользователь может создавать невозможные варианты для тестов.
- Сервер читает конфигурацию при запуске. Попытка сохраняет снимок мира при первом вызове;
  изменения файла применяются к новым попыткам после перезапуска и `reset`.

Агент сам сопоставляет рейсы и гостиницы с `event.location`. Отдельного объекта `request`
в конфигурации нет: бриф живёт вне файла.

## Доступ и инструменты

MCP работает через Streamable HTTP с заранее выданным Bearer-токеном. Токен определяет
владельца попытки; чужие брони и регистрации недоступны. Выпуск, отзыв, перевыпуск токенов
и сброс попытки выполняет оператор.

Попытка создаётся при первом вызове инструмента под токеном (отдельный `start_task` не нужен).
Аргумент `task_id` в инструменты агента не передаётся.

| Инструмент | Обязательное поведение |
|---|---|
| `list_events` | Вернуть мероприятия из снимка попытки |
| `list_flights` | Вернуть рейсы |
| `list_hotels` | Вернуть гостиницы |
| `register_for_event` | Одна регистрация = один участник (`name` обязателен; `email` — если у события `email_required`) |
| `list_registrations` | Показать регистрации попытки |
| `cancel_registration` | Отменить регистрацию; повтор безопасен |
| `book_flight` | Создать бронь рейса |
| `book_hotel` | Создать бронь при доступности всех запрошенных ночей |
| `cancel_booking` | Бесплатно отменить свою бронь |
| `list_bookings` | Показать брони, статусы и сумму активных |

Схемы аргументов доступны через `tools/list`. Ошибка операции не должна выглядеть успешной
бронью. Отказ из-за занятой ночи или неверных дат не создаёт бронь. Сервис может принять
отдельные брони и несколько регистраций, не согласованные с брифом: итоговую согласованность
проверяет оператор или будущий grader, не MCP-инструмент агента.

Инструментов `inspect_task` и `finish` на поверхности студента нет: агент не должен получать
оракул успеха через сервис.

## Ожидаемая согласованность поездки (для будущего grader)

Не реализуется сервером в этой версии. Для ручной оценки и будущей проверки:

- Нельзя заехать в гостиницу до прибытия и выехать после отъезда из города.
- Нельзя уехать раньше прибытия; нельзя сделать checkout раньше check-in.
- Нельзя прибыть после начала мероприятия; отель и рейсы должны охватывать даты события.
- `hotel.location` совпадает с `event.location`; рейсы связывают маршрут с этой локацией.
- Число активных регистраций соответствует брифу (один вызов = один участник).
- Время суток 14:00 check-in / 12:00 checkout — повествовательные умолчания; учёт пока
  по датам.

## Попытки, повторные вызовы и журнал

- Повтор одинаковой активной брони возвращает прежнюю запись, в том числе при конкурентных
  запросах. Другая гостиница, рейс или даты создают дополнительную бронь.
- Отмена исключает стоимость из активной суммы; запись остаётся в истории. Повтор отмены
  безопасен.
- Несколько регистраций разрешены API; соответствие брифу — на стороне оценки.
- Перевыпуск токена сохраняет попытку. Сброс создаёт новую попытку с новым ID, сохраняя
  старый журнал.
- Состояние и журнал операций сохраняются в SQLite транзакционно.
- Оператор получает ведомость и журнал. Токены доступа не включаются в журнал операций.

Текущие ограничения: попытка действует 2 часа, бюджет — 100 учитываемых вызовов владельца;
доступ по умолчанию действует 168 часов. Поле `student` — идентификатор владельца доступа.
Сервер подтверждает операции под доступом, но не авторство кода, личность или участие LLM.

## Границы версии

Прямые рейсы, проживание до 14 ночей. Даты местные; часовые пояса, пересадки, трансферы,
визы и реальные тарифы за отмену не моделируются. Реальных покупок и платежей нет.
Автоматический grader, golden-question файлы и инвентарь мест на рейсах не входят в версию.

Размещение — один процесс сервера и SQLite. Удалённый доступ через HTTPS; локально —
HTTP на localhost. Полноценные OAuth/SSO и распределённое развёртывание не входят в версию.

## Проверка изменений

| Область | Где проверять |
|---|---|
| Конфигурация и примеры | `tests/test_config.py` |
| Снимок мира, брони, RSVP, доступы | `tests/test_store.py`, `tests/test_travel.py` |
| Настоящий MCP по HTTP, схемы и границы доступа | `tests/test_http.py` |

Для изменения правил нужны проверка ожидаемого результата и правдоподобный отрицательный
пример. Тесты сервиса не подтверждают качество LLM-агента. В отчёте указывается только
выполненная проверка.
