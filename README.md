# agent-travel-playground

Песочница для тестирования AI-агентов, организующих поездки на мероприятия.
MCP-сервис предоставляет каталоги, регистрации и брони без реальных покупок.
Бриф передайте агенту сами; итоговую поездку оценивайте вручную.

## Запуск

Python 3.11+. Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r service/requirements.txt
python service/admin.py new-token local-user
python service/server.py
```

`new-token` печатает Bearer-токен. Подключите агента к `http://127.0.0.1:8000/mcp`
с заголовком `Authorization: Bearer <token>`. Для удалённого подключения нужен HTTPS.

Альтернативный запуск через фабрику Uvicorn:

```bash
uvicorn server:create_app --app-dir service --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Минимальный Python-клиент: [examples/mcp_client.py](examples/mcp_client.py)
с функциями `connect`, `schemas`, `call`.

## Конфигурация

По умолчанию сервис использует БД `data/verification.sqlite3` и каталог
[config/events.json](config/events.json). Пути переопределяются переменными
`VERIFY_DB` и `VERIFY_CONFIG`; в командах оператора также доступны `--db` и `--config`.

Каталог содержит три списка. Даты — `YYYY-MM-DD`, цены — целые неотрицательные учебные рубли.

| Список | Поля записи |
|---|---|
| `events` | `id`, `name`, `description`, `location`, `start_date`, `end_date`, необязательный `email_required` (по умолчанию `false`) |
| `flights` | `id`, `origin`, `destination`, `depart_date`, `arrive_date`, `price_rub` |
| `hotels` | `id`, `name`, `location`, `nightly_price_rub`, `available_nights` — даты начала доступных ночей |

ID уникальны внутри списка; строки непустые. Конец мероприятия и прибытие рейса
не могут быть раньше начала мероприятия и вылета соответственно. Список мероприятий
непустой; неизвестные поля и неверные типы отклоняются.

Каталог проверяется при запуске и перечитывается при каждом выполнении инструмента.
Правки видны без перезапуска и сброса попыток. В ходе попыток сохраняйте смысл ID
используемых предложений: маршрут и даты рейса, локацию гостиницы.
Некорректный каталог прерывает запуск; если он испортился во время работы,
операция возвращает `invalid_config` без изменения броней и регистраций. Этот отказ
учитывается в бюджете и журнале. Исправьте файл и повторите вызов.

Брифы [config/golden-tasks.json](config/golden-tasks.json) сервер не загружает.
В промпт агенту копируйте только `prompt`. Варианты: `easy`, `middle`, `hard`;
на `hard` нужна пересадка через несколько отдельных броней рейсов.

## Инструменты агента

- `list_events`, `list_flights`, `list_hotels` — каталоги.
- `register_for_event` — регистрация одного участника; каждый вызов создаёт новую запись.
  `email` обязателен, если у мероприятия `email_required=true`.
- `list_registrations`, `cancel_registration` — просмотр и отмена регистраций.
- `book_flight`, `book_hotel` — бронирование рейса или номера.
- `list_bookings`, `cancel_booking` — просмотр и отмена броней.

Полные схемы аргументов (`inputSchema`) и результатов (`outputSchema`), описания и
аннотации доступны через MCP `tools/list`; схемы также возвращает `schemas` клиента.
Результат содержит `ok` и при отказе `error`, передаётся в `structuredContent` и
JSON-тексте. Отказ отмечен `isError=true`. Аргументы, отклонённые схемой до выполнения,
не расходуют бюджет попытки. Внутренние ошибки возвращают общее сообщение клиенту.

Повтор одинаковой активной брони возвращает прежнюю запись с исходной стоимостью,
в том числе при конкурентных вызовах, изменении цены или удалении предложения.
Другое предложение или даты создают дополнительную бронь. Новые брони используют
текущий каталог. Отмена брони или регистрации идемпотентна: запись получает статус
`cancelled` и остаётся в списке. Активная сумма учитывает только действующие брони.

Гостиница бронируется на 1–14 ночей `[check_in, check_out)`; все ночи должны быть доступны.
Пересадка — несколько отдельных рейсов. Учёт ведётся по датам без времени и часовых поясов.
Сервис разрешает отдельные брони и регистрации, не согласованные между собой или с брифом.

## Доступ и попытки

Токен определяет владельца; чужие брони и регистрации недоступны. Попытка создаётся
при первом вызове инструмента. Лимиты по умолчанию:

| Ограничение | Значение |
|---|---|
| Срок токена | 168 часов; задаётся через `new-token --hours` |
| Срок попытки | 2 часа |
| Бюджет попытки | 100 вызовов |
| Частота HTTP-запросов | 120 в минуту на владельца |
| Размер HTTP-запроса | 16 КиБ |

## Команды оператора

Выполняются локально из корня проекта. `--db ПУТЬ` и `--config ПУТЬ` указывайте
перед именем команды. Все команды, кроме `check-config`, работают при недоступном каталоге.

| Команда после `python service/admin.py` | Действие |
|---|---|
| `new-token local-user --hours 24` | Выдать или перевыпустить токен, сохранив попытку |
| `revoke local-user` | Отозвать доступ |
| `reset local-user travel` | Сбросить попытку: следующий вызов создаст новую с новым ID, сроком и бюджетом; токен и старый журнал сохраняются |
| `clear-bookings` | Очистить брони всех пользователей |
| `report` | Вывести CSV-ведомость доступов и попыток |
| `events local-user` | Вывести журнал действий владельца в JSONL |
| `check-config` | Проверить каталог и вывести список мероприятий |

`clear-bookings` очищает все брони рейсов и гостиниц в текущих попытках, включая
отменённые записи и попытки с истёкшим сроком или отозванным доступом. Токены,
регистрации, ID/сроки/бюджет попыток и прочие сохранённые поля сохраняются.
Команда печатает число удалённых записей: `{"bookings_cleared": 3}`; повтор возвращает ноль.
Очистка атомарна и не требует перезапуска сервера; после неё агенты могут бронировать заново
в пределах оставшегося срока и бюджета. Операторские команды не доступны как MCP-инструменты.

## Данные и журнал

Брони и регистрации хранятся в SQLite вместе с журналом вызовов MCP-инструментов.
Изменение состояния и запись аргументов, результата, времени, владельца и ID попытки
фиксируются одной транзакцией; некорректный результат вызывает откат. Журнал прежних
действий сохраняется при сбросе попытки и массовой очистке броней. Внутренние трейсы
работы агента не собираются.

Диагностические логи идут в stderr через Python `logging` и содержат метаданные
операций без токенов, имён и email участников. Подробности ошибок реализации доступны
в серверных логах; полные аргументы и результаты действий — через `events`.

Существующие SQLite-файлы читаются без пересоздания таблиц. Старые попытки сохраняют
брони, регистрации, ID, сроки, результаты и журнал; отдельные поля старых записей
могут отсутствовать. При следующем выполнении операции устаревшая копия каталога
исключается из состояния; остальные поля сохраняются.

## Docker (опционально)

```bash
docker build -t agent-travel-playground .
docker volume create agent-travel-playground-data
docker run -d --name agent-travel-playground \
  -p 127.0.0.1:8000:8000 -v agent-travel-playground-data:/data \
  --mount "type=bind,source=$PWD/config,target=/app/config,readonly" \
  agent-travel-playground
docker exec agent-travel-playground python admin.py new-token local-user
```

На сервере: один worker, постоянный том `/data`, reverse proxy с HTTPS,
`VERIFY_HOSTS` / `VERIFY_ORIGINS` под ваш домен. Снаружи открывайте только HTTPS.
