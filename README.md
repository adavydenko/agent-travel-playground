# agent-travel-playground

Песочница для тестирования AI-агентов, организующих поездки на мероприятия.
MCP-сервис предоставляет каталоги, регистрации и брони без реальных покупок.
Бриф передайте агенту сами; итоговую поездку оценивайте вручную.

## Запуск

Из корня проекта:

```bash
# установка зависимостей
python3 -m venv .venv
source .venv/bin/activate
pip install -r service/requirements.txt

# выдача ключа (токена) для работы агенту
# передается в заголовке `Authorization: Bearer <token>`
python service/admin.py new-token local-user

# запуск сервера по адресу http://127.0.0.1:8000/mcp
python service/server.py
```

При запуске сервера по умолчанию используются следующие параметры: 
 - БД = `data/verification.sqlite3`, 
 - конфиг = `config/events.json`, проверяется при старте сервера

Значения могут быть переопределены через переменные окружения `VERIFY_DB` / `VERIFY_CONFIG`).

После правки `config/events.json` перезапустите сервер и сбросьте попытку
(`admin.py reset … travel`): снимок мира фиксируется при первом вызове инструмента.

## Конфигурация

[config/events.json](config/events.json) — определяет окружающий мир агента: `events` (мероприятия), `flights` (перелеты), `hotels` (гостиницы).
Даты принимаются в формет `YYYY-MM-DD`, цены — целые рубли, без копеек. Подробности полей — в требованиях.

Примеры брифов : [config/golden-tasks.json](config/golden-tasks.json) —
`easy` / `middle` / `hard`. В промпт агенту копируйте только `prompt` (без `event_id`).
На `hard` прямого рейса в город мероприятия нет: нужна пересадка (несколько броней рейсов).

Опционально (без запуска сервера) можно провалидировать свою конфигурацию: 
```bash
python service/admin.py check-config
```

## Инструменты агента

- `list_events`, `list_flights`, `list_hotels` — каталоги.
- `register_for_event` — регистрация одного участника; каждый вызов создаёт новую запись.
  `email` обязателен, если у мероприятия `email_required=true`.
- `list_registrations`, `cancel_registration` — просмотр и отмена регистраций.
- `book_flight`, `list_flight_bookings`, `cancel_flight_booking` — брони рейсов
  (с snapshot маршрута: города и даты).
- `book_hotel`, `list_hotel_bookings`, `cancel_hotel_booking` — брони гостиниц
  (название, локация, даты заезда/выезда, число ночей).

Полные схемы аргументов (`inputSchema`) и результатов (`outputSchema`), описания и
аннотации доступны через MCP `tools/list`; схемы также возвращает `schemas` клиента.
Результат содержит `ok` и при отказе `error`, передаётся в `structuredContent` и
JSON-тексте. Отказ отмечен `isError=true`. Аргументы, отклонённые схемой до выполнения,
не расходуют бюджет попытки. Внутренние ошибки возвращают общее сообщение клиенту.

Повтор одинаковой активной брони (тот же рейс; или та же гостиница и даты)
возвращает прежнюю запись с исходной стоимостью, в том числе при конкурентных
вызовах, изменении цены или удалении предложения. Другое предложение или даты
создают дополнительную бронь. Новые брони используют текущий каталог и сохраняют
снимок атрибутов предложения. Отмена брони или регистрации идемпотентна: запись
получает статус `cancelled` и остаётся в своём списке. `total_rub` в list-инструментах
учитывает только активные брони соответствующего типа.

Гостиница бронируется на 1–14 ночей `[check_in, check_out)`; все ночи должны быть доступны.
Пересадка — несколько отдельных рейсов. Учёт ведётся по датам без времени и часовых поясов.
Сервис разрешает отдельные брони и регистрации, не согласованные между собой или с брифом.

## Доступ и попытки

Токен определяет владельца; чужие брони и регистрации недоступны. Попытка создаётся
при первом вызове инструмента. Лимиты по умолчанию:

| Ограничение | Значение |
|---|---|
| Срок токена | 168 часов; задаётся через `new-token --hours` |
| Срок попытки | 2 часа |
| Бюджет попытки | 100 вызовов |
| Частота MCP-запросов | 120 в минуту на владельца |
| Размер HTTP-запроса | 16 КиБ |

## Команды оператора

Выполняются локально из корня проекта. `--db ПУТЬ` и `--config ПУТЬ` указывайте
перед именем команды. Все команды, кроме `check-config`, работают при недоступном каталоге.

| Команда после `python service/admin.py` | Действие |
|---|---|
| `new-token local-user --hours 24` | Выдать или перевыпустить токен, сохранив попытку |
| `revoke local-user` | Отозвать доступ |
| `reset local-user travel` | Сбросить попытку: следующий вызов создаст новую с новым ID, сроком и бюджетом; токен и старый журнал сохраняются |
| `clear-bookings` | Очистить брони всех пользователей |
| `report` | Вывести CSV-ведомость доступов и попыток |
| `events local-user` | Вывести журнал действий владельца в JSONL |
| `check-config` | Проверить каталог и вывести список мероприятий |

`clear-bookings` очищает все брони рейсов и гостиниц в текущих попытках, включая
отменённые записи и попытки с истёкшим сроком или отозванным доступом. Токены,
регистрации, ID/сроки/бюджет попыток и прочие сохранённые поля сохраняются.
Команда печатает число удалённых записей: `{"bookings_cleared": 3}`; повтор возвращает ноль.
Очистка атомарна и не требует перезапуска сервера; после неё агенты могут бронировать заново
в пределах оставшегося срока и бюджета. Операторские команды не доступны как MCP-инструменты.

## Данные и журнал

## Команды администратора

```bash
python service/admin.py report
python service/admin.py events local-user
python service/admin.py reset local-user travel
python service/admin.py revoke local-user
```

`new-token` повторно меняет токен, сохраняя попытку. По умолчанию токен действует 168 часов
(`--hours 24` — другой срок). У попытки — 2 часа с первого вызова и бюджет 100 вызовов.

## Запуск Docker (опционально)

```bash
# сборка контейнера
docker build -t agent-travel-playground .
docker volume create agent-travel-playground-data

# запуск
docker run -d \
  --name agent-travel-playground \
  -p 127.0.0.1:8000:8000 \
  -v agent-travel-playground-data:/data \
  --mount "type=bind,source=$PWD/config,target=/app/config,readonly" \
  agent-travel-playground

# генерация токена
docker exec agent-travel-playground python admin.py new-token local-user
```

На сервере: один worker, постоянный том `/data`, reverse proxy с HTTPS,
`VERIFY_HOSTS` / `VERIFY_ORIGINS` под ваш домен. Снаружи нужно открыть только HTTPS.

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты покрывают конфигурацию, брони, RSVP, доступы и локальный MCP по HTTP; LLM не вызывают.

Слои в `service/`:

| Модуль | Граница |
|---|---|
| `contracts.py` | Типы каталога, state и результатов инструментов |
| `catalog.py` | Загрузка и проверка JSON-каталога |
| `travel.py` | Домен: правила мира над `State` (без БД и MCP) |
| `store.py` / `db/` | Доступы, попытки, audit; `execute` вызывает travel-ops |
| `server.py` | MCP/HTTP: FastMCP, auth, лимиты; тонкая обёртка над Store |
| `admin.py` | Операторский CLI над Store |
